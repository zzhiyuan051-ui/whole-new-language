# 洄文推广方案：从"找腾讯"到真正让更多人用上

> 本文回答一个问题：**洄文已经做出来了，怎么让更多人真的用它？**
> 结论可能和你原本的设想不同：**「联系 QQ 官方」不是第一步，也不是最有效的一步。**
> 本文说明为什么，以及替代方案。
>
> 数据来源均为本仓库可复算的脚本（`tools/char_audit.py`、`tools/codepoint_table.py`），
> 不是估计值。官方要求引自 <https://sew.unicode.org/guidelines>（2026-10 实测）。
> **引用时请勿用 `unicode.org/guidelines`** —— 那是 404 的旧地址。

## 一、先看清你手里有什么

我直接解析了 `font/GalHuiwen.ttf` 的 `cmap` 表，结果如下：

| 项 | 实测值 | 说明 |
|---|---|---|
| 字体文件 | `font/GalHuiwen.ttf`，2,045,412 字节 | em=1000，`GalHuiwen Regular` |
| 字形数 | **3,001** | 含 1 个 `.notdef` |
| **已编码码位** | **3,000** | U+E000 – U+EBB7，**连续一整段** |
| 码位性质 | **100% 私用区（PUA）** | 私用区外 **0 个** |
| 私用区占用率 | **46.9%** | BMP 私用区 U+E000–U+F8FF 共 6,400 位 |
| 备用字（已成形待指派） | 12,000 | **尚未编入字体**（无码位） |
| 词表 | 3,000 条 | 词根 480 + 派生 2,488 + 虚词 32 |
| 语义类 | 44 类（class_no 0–43） | 其中 **20 类**有已定义字符，**24 类**仅有备用字 |
| 已实现工具 | TSF 输入法（C++，COM 已验证）、钩子版、字体生成链、125 页字表、131.8 万字双语大字典 | 完成度远超"只有字体文件" |

**README 里有一处需要更正**（不是错误，是容易被误读）：

> README §一 与 §四 称 `font/GalHuiwen.ttf` 是「真字体（15000 字形）」。
> 实测是 **3,001 字形 / 3,000 码位**。12,000 个备用字**只在 `characters.tsv` 与渲染工具里成形，
> 没有进字体**。这在技术上完全合理（备用字无音无义，不该占码位），
> 但对外行文时必须说清楚 —— **提案里说"我有 15000 字"会被核实为谎报**。
> 建议改成「已定义 3,000 字（已编码）＋ 备用 12,000 字（已成形待指派）」。

## 二、必须知道的机制事实：为什么"私用区"决定了你的处境

这不是理论，是一条能精确预测失败位置的机制。

> **私用区码位的含义不由任何标准规定，而由"使用它的各方私下约定"。**
> —— [Unicode 官方 FAQ](https://www.unicode.org/faq/private_use.html)

于是发生这件事：

| 场景 | 结果 | 原因 |
|---|---|---|
| 你在自己电脑上打字 | ✅ 正常 | 你机器上有 `GalHuiwen.ttf`，你的输入法按你的约定映射 |
| 你把洄文文本发给别人 | ❌ **对方看到豆腐块，或别家字体的无关字形** | 传输的是**码位**（U+E012），不是**字形**。接收方设备用自己的字体栈渲染 U+E012 —— 而那个码位在微软雅黑、思源黑体、日文 legacy 字体里都可能有完全不同的含义 |
| 对方也装了你的字体 | ✅ 显示出来 | 双方共享了同一份"私下约定" |

**关键推论：加 QQ 好友、把字体文件传过去，不解决问题。**
QQ 的聊天窗口会用**接收方系统的字体**渲染，不会用发送方附带的字体。

这解释了为什么"让 QQ 官方接受我的字体"这个思路在机制上不成立：

- PC 版 QQ 的字体**直接使用系统字体**，装了才有 —— [ZOL 问答](https://xiazai.zol.com.cn/jiqiao/38358.html)
- 腾讯的字体是**定制项目**（方正/汉仪按腾讯 VI 需求制作），不存在"来稿评审"流程 —— [方正字库定制案例](https://www.foundertype.com/index.php/FontofMade/caseDetail/id/23.html)
- 即使腾讯把字体内置进 QQ，**也只在 QQ 里显示**；一发到微信、Word、浏览器，照样是豆腐块

**你要的不是腾讯的许可，是一个全局唯一的码位。** 那是 Unicode 的事。

## 三、三条路，按「现在能不能走」排序

### 路线 A：Unicode 编码（唯一的根本解）

拿到正式编码后，QQ、微信、Word、浏览器**自动就能显示**，不需要求任何公司。
你现在的 TSF 输入法已经解决了"能打出来"，编码解决的是"打出来别人看得见"。

**这条路的闸门是一份官方原文**（[来源](https://sew.unicode.org/guidelines)）：

> **Usage**: you need to demonstrate that the characters are already in use by a community
> (**independent of the script creator, if applicable**)

**你目前只有自己一个人在用 —— 而官方把"创作者本人"明确排除在证据之外。**
所以现在提交会是 **desk rejection**：不予讨论、不公开发表、连反馈都拿不到。

**这不是坏消息，因为它把任务变明确了**：你不需要现在去说服任何人，
你需要的是**让洄文被创作者以外的人真实使用**。这也正是路线 C 的目标。

详细要求与逐条自查已写成独立文档：**[`docs/unicode-proposal-draft.md`](unicode-proposal-draft.md)**

其中一条对你**直接命中**、且被你完全控制的硬要求：

> **The Consortium will not consider proposals that are not endorsed in writing by all
> IP claimants** in the proposed characters/scripts.

洄文是原创文字，属于官方点名的 "created scripts ... in which the script creator
expressly claims copyright" 情形。**好消息是：著作权人就是你自己，这一条你签个字就过。**
但必须**现在就理清并写入提案**，不能拖到最后（届时会被要求补 CLA + 书面背书）。

### 路线 B：向腾讯递材料（该做，但要摆正期待）

**目标不是"让 QQ 内置"**（那需要腾讯有动机，而它没有），而是：

1. 拿到一份**书面回应**（哪怕是拒绝）—— 这本身在 Unicode 提案里可作为"交换需求"的辅助材料；
2. 万一撞上某个愿意试的产品线（手机 QQ 主题/字体商城、QQ 输入法皮肤、腾讯游戏内嵌字体）。

**递送入口（不是客服，客服只会转圈）：**

### 路线 C：先造出"独立使用者"（**现在唯一该全力做的事**）

这是路线 A 的前置条件，也是唯一不需要任何人批准的路线。
你说了洄文"传播性和可学性都比较强" —— 那是产品优势，不是审批优势。
**优势要在用户手里兑现，不在邮件里兑现。**

| 做法 | 为什么有效 | 你的项目已具备 |
|---|---|---|
| **公开仓库**（GitHub/Gitee）+ 开源字体 | 让全世界能下载，且**制造可被引用的公开来源**（提案硬要求） | 全部源码与规格已齐 |
| **网页版试用**（零安装） | 把"可学性"变成产品。用户 30 秒内能打出一个洄文字并导出 PNG | `font/demo.html` 已有基础 |
| **教学账号**（B站/小红书） | 冷启动最有效。你的《洄文入门》五编二十课**已是现成教材** | ✅ 教材完成度极高 |
| **输入法皮肤 / 主题包** | 安卓用户装上就能用；手机厂商主题商店门槛远低于腾讯 | TSF 版已成，需做安卓侧 |
| **游戏 MOD / 独立游戏内嵌字体** | 游戏圈对自定义字符最宽容，能快速积累真实使用场景 | 字体已可用 |
| **ConScript Unicode Registry 登记** | 非官方但被业界认可的**人造文字私用区登记处**，让"私下约定"变成公开约定，避免与他家 PUA 占用冲突 | 见下方 |

**关于 ConScript Unicode Registry（CSUR）—— 这是被严重低估的一步。**

Unicode 官方 FAQ 主动把 CSUR 举为范例：

> As an example, see the **ConScript Unicode Registry** — a private group unaffiliated with
> the Unicode Consortium — which has extensive tables listing private-use character
> definitions for various unencoded scripts.

它做的事正是你需要的：**把你对私用区的占用公开登记下来，形成"公开的私下约定"**，
从而（1）降低与他家 PUA 冲突的风险，（2）成为可被第三方引用的公开来源，
（3）向 SEW 展示你已按规矩行事。**这是当前最划算的一步：成本极低，收益直接对上游提案。**

入口：<http://www.evertype.com/standards/csur/>

## 四、腾讯这条路的具体评估（如实）

| 递送对象 | 现实概率 | 理由 |
|---|---|---|
| QQ 客服 / 意见反馈 | **0%** | 不是技术对接渠道，会被当成用户建议归档 |
| 腾讯开放平台（通用合作） | 低 | 面向已有商业合作的开发者；无用户量时会被判定为低优先级 |
| 手机 QQ 字体商城 / 主题 | **低但非零** | 这是唯一真正匹配的入口。需要：公司或个人资质、授权合同、**以及已有的用户需求** |
| QQ 输入法（皮肤/词库） | 低但非零 | 输入法皮肤是开放度较高的生态 |
| 腾讯游戏（内嵌字体） | 低 | 游戏对自定义字体需求真实存在，但决策在项目组而非公司 |
| 腾讯的字体供应商（方正/汉仪等） | **可能是最好的迂回** | 它们与腾讯有长期字体合作关系；被它们收录＝间接进入分发链 |

**一句话结论**：腾讯这条路**值得发一封，但不值得等**。
在你有独立用户之前，它不会推进；在你有了独立用户之后，**你甚至可能不需要它了** ——
因为编码一旦拿到，所有平台自动支持。

## 六、一个技术层面的建议（可能省掉你 90% 的码位需求）

洄文的字形是**算法生成**的：`字形 = f(编号)`，编号展开为 8 个基-4 数位 + 边框 + 中央类标记 + 家族纹。

这意味着你有两种根本不同的编码策略：

| | 策略 A：整体编码 | 策略 B：组件编码 |
|---|---|---|
| 编码对象 | 每个字一个码位（3,000 → 15,000） | 数位 + 边框 + 类标记 + 家族纹 |
| 码位需求 | **3,000（现）/ 15,000（满）** | **约 87 个** |
| 举证负担 | 要证明 15,000 个**都是独立字符** | 要论证用户读到的是**一个字符**而非一串组件 |
| 先例 | 女书（U+1B170，396 字）、西夏文 | 谚文 Jamo（算法组合） |

**策略 B 的码位需求小两个数量级**，而且与你"字形由编号生成"的核心设计一致。
但它有一个必须先解决的论证问题：官方明确警惕"能用既有字符序列表达的重复表示"。
洄文的组件**没有既有 Unicode 对应物**，所以不直接违反该条；
关键在于**洄文的读者心理上是"看到 8 个数位拼成一个字"，还是"一个不可拆的整体"**。

**这个问题只有你能回答，而且必须在写提案前回答。** 它决定了后面所有工作量。

## 七、这份评估的边界（如实交代）

1. **我没有向腾讯发出任何请求，也没有腾讯内部信息。** 上表概率是我的判断，不是数据。
2. **"独立使用者"的门槛我说不出具体数字。** 官方原文是"a community"，具体多少由 SEW
   个案裁量。我给出的"100 个"是我建议的自定目标，**不是官方标准**。
3. **腾讯各入口的地址经实测可访问，但我不保证它们在评审链路上有效** ——
   它们是公开的合作入口，不是"字体提案"专用通道（腾讯不存在后者）。
4. **提案时间预期 3–7 年**，依据是 ISO 官方流程阶段（委员会投票本身 1–2 年、
   询问投票 5 个月、批准投票 2 个月、ITTF 出版数月到一年以上），
   见 <https://www.unicode.org/alloc/ISOStages.html>。
5. **本文没有替你判断洄文"该不该"走向标准化。** 私用区 + CSUR 登记 + 自建输入法
   这套组合**本身就是一个自洽、可持续的方案** —— 如果你只想让同好在自己的设备上
   读写洄文，你**已经做完了**。走 Unicode 是为了"陌生人之间无需事先约定也能通信"，
   这是一个更高但更远的目标，值得单独决定。
